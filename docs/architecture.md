# Архитектура backend

Основа — архитектурные правила соседнего проекта `planner`: TypeScript,
feature-first модульный монолит, один Worker и D1. Backend и его границы
сохранены. `chatgpt/` содержит отдельно размещаемый на Sites MCP-адаптер,
который вызывает публичный HTTP-контракт готового backend; собственной БД
и прямого доступа к Meta у него нет. Общие правила — в `AGENTS.md`.

```text
backend/src/
  index.ts                       Worker entry point
  app/                           сборка HTTP-приложения
  modules/
    instagram/                   OAuth, соединения, официальный клиент Meta
    analytics/                   сбор, поиск, отчёты и расчёты
      domain/                    модели и чистые расчёты
      application/               сценарии использования и порты
      infrastructure/            адаптер Instagram, D1
      presentation/              HTTP и OpenAPI
  platform/                      окружение, схема БД, шифрование, HTTP-ошибки
  shared/application/            общие коды ошибок
```

`app` импортирует корни модулей. Между модулями разрешены только `index.ts` и
`public-contracts.ts`; `analytics` зависит от публичного `InstagramReader`.
Domain не использует сеть, БД, окружение, текущее время и генераторы ID.
Application получает конкретные порты, а инфраструктура реализует их.
Проверка границ выполняется скриптом `boundaries:check`. DI-фреймворка,
универсального репозитория, Redis, очередей и дополнительных сервисов нет.

Поиск использует нормализованные подписи и названия. Каждое слово ищется как
литеральная подстрока через `instr`, чтобы длинные названия на кириллице не
упирались в ограничение D1 на размер шаблона `LIKE`.

## Хранение

| Таблица | Назначение |
| --- | --- |
| `accounts` | Идентификатор платформы, профиль, время последнего успешного сбора |
| `instagram_connections` | Шифрованный токен, срок действия и разрешения |
| `oauth_attempts` | Хеши одноразовых state и сроки действия |
| `media` | Метаданные публикации, нормализованный поиск, локальные название и длительность |
| `media_snapshots` | Метрики, версия API и время наблюдения |
| `account_snapshots` | Наблюдения числа подписчиков и публикаций |
| `sync_runs` | Идемпотентные операции сбора и безопасные коды ошибок |
| `sync_leases` | Блокировка одновременного сбора одного аккаунта |

Метрики хранятся в JSON внутри неизменяемого снимка; каждая имеет источник,
единицу и причину отсутствия. Не сохраняются сырые ответы Meta с токенами.
Миграции генерирует Drizzle, локально их применяют до проверки проекта.

## Сбор

Операция с UUID собирает одну страницу из 1–3 публикаций. Сначала проверяется
идемпотентность, затем устанавливается блокировка аккаунта на 15 минут.
Backend проверяет принадлежность токена, получает метаданные и доступную
статистику каждой публикации. Неподдерживаемая метрика не скрывает остальные:
если Meta явно называет отклонённые поля, адаптер исключает только их и повторяет
запрос остальных метрик группой. После известного отказа кросспостинга его поля
проверяются отдельно, остальные — группой. При неопределённом отказе адаптер
проверяет каждую метрику отдельно. Доступность не переносится между публикациями.

Сохранение метаданных, снимков и результата выполняется одним атомарным D1
batch. Каждая запись проверяет текущую блокировку и её срок; опоздавший сборщик
не может записать данные после начала другой операции. При ошибке страница
целиком остаётся несохранённой, операция отмечается неудачной, её блокировка
освобождается. Ручные название и длительность синхронизация не перезаписывает.

Внешние запросы идут только на фиксированные официальные хосты. Продолжение
пагинации использует `after`, а не полученный `paging.next`, который может
содержать access token. Каждый HTTP-запрос к Meta ограничен 15 секундами.
Синхронизация постраничная, чтобы оставаться в лимите внешних запросов Worker.
Автоматический scheduler пока не добавлен.

## Доступ и OAuth

Одна установка обслуживает одного владельца. Личный Bearer-ключ защищает API;
его хеш сравнивается с хешем настроенного ключа. OAuth callback проверяет
атомарно потребляемый хеш state, действительный десять минут.

Access token никогда не возвращается клиенту. AES-GCM использует случайный IV
и ID аккаунта как дополнительные аутентифицируемые данные. Ключ шифрования и
Instagram App Secret передаются через Worker Secrets. Invocation logs отключены;
ошибки не содержат upstream payload, query string, OAuth state или код.

`Cache-Control: no-store` и `Referrer-Policy: no-referrer` действуют для всех
ответов. Для доступа к снимкам конфигурация Meta не требуется; повторный сбор
требует действующего соединения. Удаление токена сохраняет накопленную историю.
