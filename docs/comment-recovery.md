## Что подтверждено в production

Из 80 частичных публикаций 77 имеют 1 049 непроверенных веток replies.
У остальных трёх Instagram возвращает INSTAGRAM_OBJECT_UNAVAILABLE (100/33).
Непроверенные ветки не доказывают отсутствие текстов или отказ Meta: прежний
сборщик проверял только первые две omitted-ветки на публикацию, остальные
оставались за пределами очереди. При следующем проходе лимит начинался заново.
Отсутствующий replies в field expansion сохранялся как неизвестность.

Операции, оставшиеся running с 4–5 октября, определялись как expired при
чтении, но состояние в D1 не закрывалось. Исправлены ровно 2 Insights и
23 комментарных операции: status=failed, errorCode=COLLECTION_EXPIRED.
Это восстановление состояния выполнено по просьбе исправить старые попытки;
оно не объявляет источник успешно прочитанным. Исходные времена, observedAt,
другие поля payload, media counters и 3 882 сохранённых комментария сохранены.
Активные leases защищены условиями UPDATE. Резервные исходные записи
сохранены в игнорируемом tmp/collection-audit/expired-before.json.
Через установленный MCP подтверждено: expiredInsightAttempts=0,
expiredCommentAttempts=0, expiredSyncAttempts=0. Частичные публикации пока
оставались 80 до публикации нового обхода; это исходное состояние для
проверки прогресса, не итог выполненного ремонта.

Безопасное доказательство ремонта: [production JSON](attempt-recovery-production-2026-10-23.json).

## Изменения 0.3.13

Все omitted-ветки внешней страницы попадают в сохранённую очередь. Отдельный
GET replies и все его продолжения выполняются по одной странице за шаг.
Проверенная пустая data без next закрывает неизвестность; отсутствующее поле
само по себе не превращается в пустую ветку. Курсоры, lease/fence и operation
ID сохраняются. Уже проверенный parent на пересекающейся внешней странице
не запрашивается повторно в этом проходе. Недоступный parent остаётся явно
непроверенным, недоступная публикация сохраняет паузу на 24 часа; auth/rate
ошибки не списываются как пустые результаты.

Совместимое поле policy.commentPolicy.omittedProbeLimit теперь равно 50:
это максимум кандидатов из одной внешней страницы, а не предел за проход.
Старый omittedProbeCount в сохранённом cursor больше не ограничивает обход.
Сохраняется общий бюджет 6 HTTP-попыток / 90 секунд на alarm; один advance
читает одну страницу. Проверка всех веток требует дополнительных запросов
и D1-записей. Прежние измерения экономии при двух пробах не доказывают
стоимость полного обхода: в фикстуре с 62 текстами теперь 45 запросов
против прежних 3 выборочных или 51 при отдельном чтении каждой ветки.

Первый успешный alarm после обновления переносит next_refresh_at частичных
публикаций включённых аккаунтов на текущее время. Если ещё работает старый
комментарный проход, восстановление откладывается до его завершения.
Флаг восстановления сохраняется в том же DO; eviction не запускает его
заново. Очередь заполняет штатный планировщик, не отдельный ручной цикл.
Счётчик partial не сбрасывается заранее и уменьшается только по результатам
настоящих проверок. Расписание и сохранённые комментарии не стираются.

Раз в пять минут тот же DO закрывает до 100 истёкших Insights и до 100
комментарных попыток. Проверки используют существующие индексы running,
не обходят всю историю и защищают активные leases. Текущие успешные
наблюдения не меняются; старые timestamps не заменяются временем ремонта.
Сохранение результата требует всё ещё running reservation с тем же временем
начала: запоздавший ответ не оживляет закрытую попытку и не вставляет тексты.
Обычная ошибка обслуживания откладывает его повтор, сохраняя сбор доступным;
исчерпание D1 останавливает все запросы через существующий общий guard.

## Проверка и выпуск

Root pnpm check: 230 backend + 28 MCP тестов. Проверены полный обход после
первых двух omitted-веток, следующие внешние страницы, пересечения страниц,
восстановление очереди новым executor, поздние writers, свежие/активные leases,
порции 100+1 и реальный DO alarm с eviction и сохранённым интервалом.
Большая фикстура 236 публикаций / 144 tick сохраняет прежние проверки fairness;
её timeout увеличен до 30 секунд, без сокращения нагрузки или assertions.

Публикация выполнена по отдельному разрешению владельца. Порядок проверки:

1. Сохранить production baseline, опубликовать 0.3.13 с существующими bindings.
2. Проверить health, bundle и неизменность расписания/исторических снимков.
3. Дождаться штатного alarm и проверить появление comments_refresh для
   ранее частичных публикаций. Не сбрасывать неизвестные ветки ручным UPDATE.
4. Следить за фактическим уменьшением partial/unverified и приростом
   сохранённых текстов. Даже полный проход не доказывает доступность всего,
   что Meta включает в comments_count; три недоступных объекта останутся
   ограничением до успешной проверки источника.
