# Метрики и формулы

Версия адаптера — Instagram Graph API v26.0. Определения сверены с официальной
[документацией статистики медиа](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/insights/)
и [общими правилами Insights](https://developers.facebook.com/docs/instagram-platform/insights/).
Фактическая доступность зависит от типа публикации, её возраста, разрешений и Meta.

## Сохраняемые значения

| Поле backend | Поле Meta | Единица | Применимость |
| --- | --- | --- | --- |
| `views` | `views` | число | Feed, Reels, Stories |
| `reach` | `reach` | число | Feed, Reels, Stories; оценка Meta |
| `likes` | `likes` / резервное `like_count` | число | Feed, Reels |
| `comments` | `comments` / резервное `comments_count` | число | Feed, Reels |
| `saves` | `saved` | число | Feed, Reels |
| `shares` | `shares` | число | Feed, Reels |
| `reposts` | `reposts` | число | Feed, Reels, если доступно |
| `totalInteractions` | `total_interactions` | число | Feed, Reels |
| `totalWatchTimeMs` | `ig_reels_video_view_total_time` | мс | Reels |
| `averageWatchTimeMs` | `ig_reels_avg_watch_time` | мс | Reels |
| `skipRate` | `reels_skip_rate` | % | Reels; оценка Meta |
| `facebookViews` | `facebook_views` | число | Reels с кросспостингом, если доступно |
| `crosspostedViews` | `crossposted_views` | число | Reels с кросспостингом, если доступно |
| `follows` | `follows` | число | Feed, если доступно |
| `profileVisits` | `profile_visits` | число | Feed, если доступно |

При резервном источнике `sourceField` указывает именно поле медиаобъекта.
Его не складывают с одноимённой метрикой Insights. Facebook/crossposted views
хранятся отдельно; их не прибавляют автоматически к Instagram views.

`null` означает отсутствие данных. `reason`: `not_returned` — API не вернул
значение; `not_supported` — метрика неприменима или отклонена Meta;
`permission_required` — не хватает разрешения; `invalid_value` — значение
не соответствует числовому контракту. Несколько временных значений API
не суммируются произвольно. Настоящий ноль остаётся нулём.

При проверке реального аккаунта 2026-10-02 Meta отклонила `reposts` с кодом
`100`, а `facebook_views` и `crossposted_views` — с нетранзитной ошибкой
`code=-1`, `error_subcode=2207086`. Эти ответы дают `not_supported` для
соответствующей метрики; остальные показатели сохраняются. Неизвестные ошибки,
временные сбои и rate limit не маскируются как отсутствие метрик.

## Вычисляемые показатели ролика

`interactions` — `totalInteractions` от API. Если его нет, используется сумма
`likes + comments + saves + shares`, только когда известны все четыре слагаемых.

| Показатель | Формула |
| --- | --- |
| `engagementByReach` | `interactions / reach × 100%` |
| `engagementByViews` | `interactions / views × 100%` |
| `saveRate` | `saves / reach × 100%` |
| `shareRate` | `shares / reach × 100%` |
| `viewsPerReachedAccount` | `views / reach` |
| `averageWatchRatio` | `averageWatchTimeMs / (durationSeconds × 1000) × 100%` |

Нулевой знаменатель даёт `null` с `zero_denominator`, неизвестный вход —
`null` с `missing_inputs`. Каждый расчёт возвращает формулу и входные значения.
Длительность вводится вручную и помечена источником `manual`.

Среднее время относительно длительности не показывает долю людей, досмотревших
ролик. При повторных просмотрах показатель может превышать 100%; он не обрезается.
`viewsPerReachedAccount` тоже не даёт точного числа повторных просмотров: views
и reach имеют разную методику, а reach — оценочный показатель.

## История и сравнения

Для двух снимков `A` и `B` прирост просмотров — `B.views − A.views`, скорость —
прирост / число часов между наблюдениями, процент — прирост / `A.views × 100%`.
Без двух снимков возвращается `no_baseline`. При начальном нуле процент
не определён. Если счётчик уменьшился, `netChange` сохраняет отрицательное
изменение, а показатели прироста и скорости становятся `null` с
`counter_decreased`: это может быть корректировка Meta.

История возвращается от нового снимка к старому. Расчёт относится к интервалу
возвращённой страницы; `intervals` показывает каждую соседнюю пару,
`coverage` указывает наблюдения и усечение.
Чистое изменение числа подписчиков — разница между наблюдениями, а не
отдельные количества подписок и отписок.

Benchmark использует все сохранённые публикации того же product type и
аккаунта, исключая сам ролик. Для каждой метрики возвращаются медиана,
число доступных наблюдений и отношение к медиане. Возраст публикаций и время
сбора могут различаться; сравнение не нормализовано по возрасту.

Сводка аккаунта использует весь выбранный сохранённый каталог. Даты фильтруют публикацию;
показатели — последние накопленные lifetime values, а не активность за период.
Полная сумма `value` доступна, только если значения есть у всех публикаций
и выборка не усечена. `knownSum` — сумма известных значений с явным покрытием.
Охват разных публикаций не складывается из-за пересечения аудитории.

Отдельный `/content-analysis` сравнивает первые 1/7/30 дней по настоящим
снимкам с допуском ±6/12/24 часа. Lifetime benchmark выше не является таким
сравнением. Для каждой publication указаны snapshot ID, фактический возраст,
свежесть, абсолютное значение, отношение `metric / reach`, медиана и выборка
peers того же product type/API version. Минимум peers — пять; ≥1.5 медианы
даёт above_usual, ≤0.5 — below_usual. Нулевая/недостаточная база не даёт
оценки. Группы по рубрике, формату, теме, длительности, часу и частоте показывают
медиану, квартили, диапазон и достаточность данных; это наблюдения, не причинность.

Для повторного всплеска нужен ролик возрастом ≥30 дней, последний прирост ≥100,
скорость ≥3 медиан трёх предшествующих валидных интервалов и положительная база.
Интервалы длиннее семи суток не служат доказательством ослабления/всплеска.
Снижение счётчика — корректировка, а не отрицательная скорость интереса.
Версия формул возвращается в разборе периода и анализе контента.

## Активность аккаунта и демография

Account Insights — отдельные данные источника за `[from,to)`. Сохраняются
запрошенный период/timezone/type, настоящий source period/endTime, provider,
scope, API version, unit/sourceField и observedAt. `total_value` читается как
итог указанного периода; `time_series` сохраняет отдельные точки. Дневные
reach, разные периоды и категории не складываются в уникальную аудиторию.

`follows_and_unfollows` с follow_type хранит возвращённые категории подписок
и отписок. Разница двух followers_count остаётся отдельным netChange, не
подменяет эти значения и не приписывается конкретному ролику. Поддержка всех
metric/type/breakdown сочетаний проверяется отдельно и может отсутствовать.
Сравнение равных по длительности периодов: current−previous, затем
`(current−previous)/previous ×100%`, только при известных значениях и
положительной базе; нулевая база даёт zero_denominator.

Follower и engaged audience demographics сохраняются отдельно по Meta
timeframe и dimension age/gender/country/city. Минимальная аудитория, верхние
категории и rolling окна ограничивают сравнение. Percent = category/total×100%
только при возвращённом положительном total_value; если Meta вернула только
breakdowns, проценты — null. Сумма верхних категорий не означает размер аудитории.

В v20.0+ engaged audience использует только `this_month` (последние 30 дней)
и `this_week` (последние 7 дней). `last_14_days`, `last_30_days`, `last_90_days`
и `prev_month` удалены для этой метрики; Instagram может ответить HTTP 200 с
пустыми results. Совместный сбор двух аудиторий принимает только поддерживаемые
окна. Старые сохранённые follower-окна остаются доступны для чтения.
`availableCategories` отличает сохранённые категории от неизвестного общего
знаменателя. Meta code 3006 сохраняется как `insufficient_audience`, а не ноль.

История профиля читает все сохранённые наблюдения через `nextCursor` с теми же
accountId/from/to. До 100 записей — размер страницы. `coverage.totalObservations`
и границы описывают весь выбранный диапазон; `followerNetChange` считается между
его первым и последним наблюдениями независимо от размера страницы. Изменение
не складывается между страницами и не является валовыми подписками/отписками.
Начало сохранённой истории не означает дату создания аккаунта.

После полного каталога создаются отдельные задания демографии и комментариев
при выданном manage_comments. Массовый сбор комментариев проходит весь локальный
каталог Feed/Reels и все доступные страницы ответов, включая пустые страницы с
nextCursor. `mediaProcessed` — законченные публикации, `collected` — наблюдения
текстов, которые могут включать повторное чтение. Полный проход подтверждает
исчерпание пагинации, но не доступность каждого текста из comments_count.
При включённом расписании ежедневный сбор активности ставит эти задания снова;
если предыдущий проход продолжается, он не дублируется. Отключение расписания
останавливает автоматические задания, сохраняя отдельно заказанные ручные.

## Stories и внешние результаты

Stories сохраняют views, reach, replies и navigation с категориальными полями
источника. Navigation — действия, не уникальные люди. Нельзя вывести точный
completion/retention из навигации или отношения reach соседних Stories.
Пропущенную историю до первого discovery сервис не восстанавливает.

Внешние результаты сохраняются как отдельные записи приращений с источником,
интервалом, единицей, атрибуцией и временем записи. Известные production_hours
суммируются отдельно, валюты не смешиваются. Формулы:

| Показатель | Формула |
| --- | --- |
| leadsPerHour / salesPerHour | leads или sales / production_hours |
| revenuePerCost | revenue / production_cost в одной валюте; это отношение выручки к затратам |
| profitPerHour | известная net profit / production_hours, отдельно по валютам |
| returnOnCost | известная net profit / production_cost в одной валюте |

Нет времени/затрат/результата — null. Выручка не превращается в ROI или прибыль.
Эффективность и гипотезы не доказывают причинную атрибуцию продаж публикации.

## Границы достоверности

Instagram Insights может отставать на срок до 48 часов. Account user metrics
могут быть доступны за последние 90 дней, media metrics — до двух лет,
с дополнительными ограничениями Meta. Это разные окна, ни одно не обещает
ежедневную историю отдельной публикации. Сервис использует органическую статистику
Instagram. Рекламные и объединённые показатели, показанные в приложении,
могут отличаться. Нельзя восстановить дневной прирост за время до первого
снимка или кривую удержания из одного среднего времени просмотра.
Backend явно возвращает время сбора и возраст данных.
