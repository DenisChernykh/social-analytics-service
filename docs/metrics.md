# Метрики и формулы

Instagram Login, graph.instagram.com, запрошенная версия v26.0. Определения
новых наблюдений — `instagram-measurement-v2`; старое неизвестное происхождение
не переписывается. Единственный словарь кода —
[metric-definitions.ts](../backend/src/modules/analytics/domain/metric-definitions.ts),
он же выдаётся `describe_metrics`. Определения сверены с официальной
[документацией статистики медиа](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/insights/)
и [общими правилами Insights](https://developers.facebook.com/docs/instagram-platform/insights/).
Фактическая доступность зависит от типа публикации, её возраста, разрешений и Meta.

## Сохраняемые значения

| Поле backend | Поле Meta | Единица | Применимость |
| --- | --- | --- | --- |
| `views` | `views` | число | Feed, Reels, Stories |
| `reach` | `reach` | число | Feed, Reels, Stories; оценка Meta |
| `likes` | `likes` / резервное `like_count` | число | Feed, Reels |
| `comments` | `comments` / резервное `comments_count` | число | Feed, Reels |
| `saves` | `saved` | число | Feed, Reels |
| `shares` | `shares` | число | Feed, Reels, Stories |
| `reposts` | `reposts` | число | Feed, Reels, Stories, если доступно |
| `totalInteractions` | `total_interactions` | число | Feed, Reels, Stories |
| `totalWatchTimeMs` | `ig_reels_video_view_total_time` | мс | Reels |
| `averageWatchTimeMs` | `ig_reels_avg_watch_time` | мс | Reels |
| `skipRate` | `reels_skip_rate` | % | Reels; оценка Meta |
| `facebookViews` | `facebook_views` | число | Feed, Reels, Stories с показами в Facebook, если доступно |
| `crosspostedViews` | `crossposted_views` | число | Reels с кросспостингом, если доступно |
| `follows` | `follows` | число | Feed, Stories, если доступно |
| `profileVisits` | `profile_visits` | число | Feed, Stories, если доступно |

При резервном источнике `sourceField` указывает именно поле медиаобъекта.
Его не складывают с одноимённой метрикой Insights. Facebook/crossposted views
хранятся отдельно; их не прибавляют автоматически к Instagram views.

`null` означает отсутствие значения; 0 — настоящее полученное значение. Причины:
`not_requested` — текущая политика не запрашивала поле; `not_returned` — источник
не вернул значение; `not_supported` — явное доказательство неприменимости;
`permission_required`, `insufficient_audience`, `invalid_value`, `invalid_request`,
`invalid_breakdown`, `object_unavailable`, `source_error`, `request_deferred`.
Возраст <48h и пустой ответ сами по себе не устанавливают not_ready.
Object unavailable не означает удаление. Несколько временных значений не
суммируются произвольно. Старое число не копируется в новую пустую observation.

Graph code 100 без явного доказательства неприменимости не попадает в отрицательный
capability cache. Cache v2 относится к account/Login/API/object/существенным
параметрам, действует 24h. Старые широкие cache-записи не используются; обычный
бюджет постепенно перепроверяет поля. В аудите отказ конкретного Reels для
follows/profile_visits/profile_activity и противоречие документации оставлены
как граница проверки. Текущая политика запрашивает эти поля для FEED/STORY;
дневной прирост аккаунта не подставляется как подписки от Reels.

## Вычисляемые показатели ролика

Native `totalInteractions` сохраняется отдельно; `interactionComponents.sum` —
сумма четырёх компонентов с собственным смыслом. `interactionBasis` указывает,
какое число использовано в производном расчёте. Если native нет, используется сумма
`likes + comments + saves + shares`, только когда известны все четыре слагаемых.

| Показатель | Формула |
| --- | --- |
| `engagementByReach` | `interactions / reach × 100`, действия на 100 охваченных аккаунтов |
| `engagementByViews` | `interactions / views × 100`, действия на 100 просмотров |
| `saveRate` | `saves / reach × 100`, сохранения на 100 охваченных аккаунтов |
| `shareRate` | `shares / reach × 100`, пересылки на 100 охваченных аккаунтов |
| `viewsPerReachedAccount` | `views / reach` |
| `averageWatchRatio` | `averageWatchTimeMs / (durationSeconds × 1000) × 100%` |

Нулевой знаменатель даёт `null` с `zero_denominator`, неизвестный вход —
`null` с `missing_inputs`. Каждый расчёт возвращает формулу и входные значения.
Длительность вводится вручную и помечена источником `manual`.
Числитель и знаменатель принадлежат одной сохранённой observation: единицы,
Login/API, определения и поверхность совместимы; времена ответов отличаются
не более чем на 60s. Явно противоречивые organic/includes_paid области не
смешиваются. Unknown paid coverage остаётся видимым и не считается organic;
отношение таких источниковых чисел — описательное, без доказательства paid/organic
эквивалентности. Legacy-пара использует одну observation, её определения unknown.
Отсутствующий числитель не становится нулём. Действия/100 не означают процент
уникальных людей и не обрезаются до 100. Native 141 и сумма 137, либо native 36
и сумма 35, допустимы; причина разницы может быть неизвестна.

Среднее время относительно длительности не показывает долю людей, досмотревших
ролик. При повторных просмотрах показатель может превышать 100%; он не обрезается.
`viewsPerReachedAccount` тоже не даёт точного числа повторных просмотров: views
и reach имеют разную методику, а reach — оценочный показатель.

## История и сравнения

Для двух снимков `A` и `B` прирост просмотров — `B.views − A.views`, скорость —
прирост / число часов между наблюдениями, процент — прирост / `A.views × 100%`.
Без двух снимков возвращается `no_baseline`. При начальном нуле процент
не определён. Если счётчик уменьшился, `netChange` сохраняет отрицательное
изменение, отрицательные gain/perHour/percent тоже сохраняются с диагностикой
`counter_decreased`: отмены действий и пересмотр Meta не исправляются автоматически.

История возвращается от нового снимка к старому. Расчёт относится к интервалу
возвращённой страницы; `intervals` показывает каждую соседнюю пару,
`coverage` указывает наблюдения и усечение.
Чистое изменение числа подписчиков — разница между наблюдениями, а не
отдельные количества подписок и отписок.

Benchmark использует сохранённые публикации того же product type, media type,
API/определения/области поля и аккаунта, исключая сам ролик. Для каждой метрики возвращаются медиана,
число доступных наблюдений и отношение к медиане. Возраст публикаций и время
сбора могут различаться; сравнение не нормализовано по возрасту.

Сводка аккаунта использует весь выбранный сохранённый каталог. Даты фильтруют публикацию;
показатели — последние накопленные lifetime values, а не активность за период.
Полная сумма `value` доступна, только если значения есть у всех публикаций
и выборка не усечена. `knownSum` — сумма известных значений с явным покрытием.
Охват разных публикаций не складывается из-за пересечения аудитории.

`/content-analysis` сравнивает 1/7/30 дней по настоящим снимкам с допуском
±6/12/24h. Выбирается ближайшая пригодная observation; равное расстояние
разрешается по observedAt, затем ID. Для коэффициента выбирается пригодная пара,
а не all-null snapshot или ближайший снимок с нулевым знаменателем. Подходящее
наблюдение до подключения аккаунта или в ещё открытом окне остаётся пригодным.

`rankingMode`: absolute (совместимый default), per_100_reach, per_100_views.
Меняются сортировка, baseline и групповые описания. `100 × saves/reach` и
`100 × shares/views` имеют разные знаменатели. FEED IMAGE/VIDEO/CAROUSEL_ALBUM
не объединяются в peers незаметно. Совпадают product/media type, API/Login,
определения/области, возраст с tolerance и известные rubric/topics/promotion.
Подтверждённые boost, коммерческое сотрудничество и coauthor независимы;
unknown не означает organic. Proposed context не подменяет confirmed.

Группы возвращают медиану индивидуальных коэффициентов, n и отдельно
`100 × sum(numerator)/sum(denominator)` по тем же валидным парам, их суммы и
exclusions. Это разные статистики. Сумма per-media reach не уникальна для аккаунта.
Пять peers — продуктовая эвристика для above_usual/typical/below_usual, а не
статистическая значимость. При n=1–2 сохраняется описательный результат и
предупреждение крайне малой выборки; время публикации и темы не доказывают
причинность при любом n. Группы пересекаются. Skip/average watch не объединяются
произвольными весами: initial views не равны views; общего skip или общего avg
watch из sum(totalWatchTime)/sum(views) сервис не изобретает.

Для повторного всплеска нужен ролик возрастом ≥30 дней, последний прирост ≥100,
скорость ≥3 медиан трёх предшествующих валидных интервалов и положительная база.
Интервалы длиннее семи суток не служат доказательством ослабления/всплеска.
Снижение счётчика — корректировка, а не отрицательная скорость интереса.
Версия формул возвращается в разборе периода и анализе контента.

## Активность аккаунта и демография

Account Insights — отдельные данные источника за запрошенный `[from,to)`. Сохраняются
запрошенный период/timezone/type, настоящий source period/endTime, provider,
scope, API version, unit/sourceField и observedAt. `total_value` читается как
итог ответа для запрошенного диапазона; `time_series` сохраняет отдельные точки.
Source period/end_time не заменяется локальными полуночами. Дневные
reach, разные периоды и категории не складываются в уникальную аудиторию.

Сбор активности поддерживает 12 полей: views, reach, accounts_engaged,
total_interactions, likes, comments, saves, shares, replies, profile_links_taps,
follows_and_unfollows, reposts. `time_series` разрешён только для reach без
разбивки. Для `total_value` допустимы `media_product_type`, `follow_type`,
`follower_type`, `contact_button_type` с совместимыми метриками. При отсутствии
явного списка сервис выбирает совместимые поля; явно несовместимое сочетание
отклоняется до запроса к Meta. Фактический отказ поддерживаемого поля сохраняет null.

`follows_and_unfollows` с follow_type хранит возвращённые категории подписок
и отписок. Разница двух followers_count остаётся отдельным netChange, не
подменяет эти значения и не приписывается конкретному ролику. Поддержка всех
metric/type/breakdown сочетаний проверяется отдельно и может отсутствовать.
Сравнение равных по длительности периодов: current−previous, затем
`(current−previous)/previous ×100%`, только при известных значениях и
положительной базе; нулевая база даёт zero_denominator.

Follower и engaged audience demographics сохраняются отдельно по Meta
timeframe и dimension age/gender/country/city. Минимальная аудитория, верхние
категории и rolling окна ограничивают сравнение. Percent = category/total×100%
только при возвращённом положительном total_value; если Meta вернула только
breakdowns, проценты — null. Сумма верхних категорий не означает размер аудитории.

В v20.0+ engaged audience использует только `this_month` (последние 30 дней)
и `this_week` (последние 7 дней). `last_14_days`, `last_30_days`, `last_90_days`
и `prev_month` удалены для этой метрики; Instagram может ответить HTTP 200 с
пустыми results. Совместный сбор двух аудиторий принимает только поддерживаемые
окна. Старые сохранённые follower-окна остаются доступны для чтения.
`availableCategories` отличает сохранённые категории от неизвестного общего
знаменателя. Meta code 3006 сохраняется как `insufficient_audience`, а не ноль.

История профиля читает все сохранённые наблюдения через `nextCursor` с теми же
accountId/from/to. До 100 записей — размер страницы. `coverage.totalObservations`
и границы описывают весь выбранный диапазон; `followerNetChange` считается между
его первым и последним наблюдениями независимо от размера страницы. Изменение
не складывается между страницами и не является валовыми подписками/отписками.
Начало сохранённой истории не означает дату создания аккаунта.

После полного каталога создаются отдельные задания демографии и комментариев
при выданном manage_comments. Массовый сбор комментариев проходит весь локальный
каталог Feed/Reels и все доступные страницы ответов, включая пустые страницы с
nextCursor. `mediaProcessed` — законченные публикации, `collected` — наблюдения
текстов, которые могут включать повторное чтение. Полный проход подтверждает
исчерпание пагинации, но не доступность каждого текста из comments_count.
При включённом расписании ежедневный сбор активности назначает демографию,
а полный проход комментариев — если последний завершённый старше 30 дней.
Если предыдущий проход продолжается, он не дублируется. Отключение расписания
останавливает автоматические задания, сохраняя отдельно заказанные ручные.

## Stories и внешние результаты

Stories запрашивают views, reach, shares, reposts, total_interactions,
facebook_views, follows, profile_visits и replies совместным запросом.
Navigation читается отдельно с `story_navigation_action_type`; сохраняются
категории и исходный общий итог `navigationTotal`, без подмены суммой
вернувшихся категорий. В старых снимках общий итог может отсутствовать.
Meta code 10 с сообщением о недостаточном числе зрителей даёт
`insufficient_audience`, а обычный отказ разрешения — `permission_required`.
Navigation — действия, не уникальные люди. Нельзя вывести точный
completion/retention из навигации или отношения reach соседних Stories.
Пропущенную историю до первого discovery сервис не восстанавливает.

Полная матрица покрытия, оставшиеся пробелы и оценка стоимости сбора:
[аудит API от 2026-10-08](api-collection-audit.md). Изменения матрицы Stories
и Account Insights дополнены profile_activity/action_type и расширенными
метаданными. Точная календарная история, null и ограничения новых полей описаны
в [collection-improvements.md](collection-improvements.md).

Внешние результаты сохраняются как отдельные записи приращений с источником,
интервалом, единицей, атрибуцией и временем записи. Известные production_hours
суммируются отдельно, валюты не смешиваются. Формулы:

| Показатель | Формула |
| --- | --- |
| leadsPerHour / salesPerHour | leads или sales / production_hours |
| revenuePerCost | revenue / production_cost в одной валюте; это отношение выручки к затратам |
| profitPerHour | известная net profit / production_hours, отдельно по валютам |
| returnOnCost | известная net profit / production_cost в одной валюте |

Нет времени/затрат/результата — null. Выручка не превращается в ROI или прибыль.
Эффективность и гипотезы не доказывают причинную атрибуцию продаж публикации.

## Происхождение, свежесть и календарные ревизии

Новый HTTP attempt имеет UUID и operationId логической работы. Receipt содержит
безопасную сигнатуру endpoint/metric/period/timeframe/breakdown/since/until,
requestStartedAt/responseReceivedAt либо failedAt, requested/actual API, Login,
HTTP/Graph code/subcode и классификацию. Retry имеет новый receipt, завершённая
operation повторно не читает источник и не создаёт второй snapshot.
Это компактное подтверждение, не полный raw-архив: ограниченный очищенный sample
≤4096 символов (usage header ≤2048), никаких Authorization, токенов, OAuth
code/state, подписанных URLs, имён или текстов комментариев. Числовые Graph codes
сохраняются. Чистка sample старше 7d/receipt старше 30d ограничена 100 строками
на первом завершении запроса экземпляра транспорта; без новых запросов срок
фактической очистки не гарантируется. Обычный MCP не читает транспортный журнал.

Profile observedAt — время собственного ответа. Media observation задаёт границы
последовательных запросов, per-field receipt и единицу/определение/поверхность;
она не обещает атомарное одновременное чтение Meta. `freshness` разделяет lastAttempt
и lastKnownGood с исходным временем. Новая ошибка/null не освежает good value.
Из lastKnownGood разных времён не формируется новый коэффициент.

Новая коллекция комментариев сохраняет receipt и definitionVersion в существующем
JSON операции; observedAt страницы/её строк берётся из responseReceivedAt.
`commentIds` связывает страницу с сохранёнными строками. `comment.likeCount`
описывает native like_count, отдельно от comments-counter публикации. Строки
комментариев обновляемы: это текущая сохранённая выборка, не полный неизменяемый
архив исторических like_count/текстов. Legacy collections без receipt остаются unknown.

Календарная задержка — версионированная политика 48h (`account-delay-v1`), не
source_final. Отдельны periodEnded/sourceDelayElapsed/observedAfterDelay/recheckDue/
matureByPolicy. Позднее чтение — новая ревизия одного periodKey. Перевод часов
не меняет ранний reading. Для составного результата maturity опирается на самый
ранний полезный receipt; legacy/collection timestamp помечен отдельным basis.
Разные ревизии не суммируются. Возможность дальнейшего пересмотра сохраняется.

Внутренние guards 90d и 31×24h ограничивают запросы сервиса; это не универсальный
лимит всех полей Meta. Backfill сортируется по приближению окончания этого guard,
без объявления уже сохранённых июльских интервалов потерянными. Literal timeframe
и population демографии сохраняются; engaged this_month rolling 30d не переносится
автоматически на follower_demographics. Структуры при scalar null сохраняются;
доля всей аудитории без известного source total остаётся null.

## Сбор и покрытие

`analysisCoverage` учитывает реальные пригодные значения выбранной метрики/пары.
Обзор возрастных окон в collection status явно отмечен `metric=reach`,
`rankingMode=absolute`; это не покрытие всех полей. `analyze_content` вычисляет
покрытие выбранной metric и, в относительном режиме, совместимой пары.
`collectionCoverage`/`collectionObligations` учитывает лишь записанные интервалы
политики, подключение, известную доступность и минимум 5 минут возможности в окне.
Это оценка обязательств при известных условиях, не восстановленный исторический SLA.
Too young, open/closed, connected_after_window, disabled/unknown policy и
missingEligible различаются. All-null снимок не закрывает числовое покрытие.
Discovery history_inferred не входит в измеренный denominator; denominator=0
означает not_measured, а не отсутствие задержек.

Статус читает D1; сбор запускается командой либо Cron. Один tick — одна ограниченная
атомарная порция, до 6 реальных HTTP attempts и 90s с резервом 15s на запись.
Приоритеты — discovery/возрастные deadlines/Stories/истекающий calendar guard;
архив получает каждый третий свободный от близкого deadline слот. Указанная
мощность и overload — оценка с условиями, не гарантия при недоступной Meta.
Discovery по умолчанию остаётся 60 минут, Cron 5 минут; частоты не сокращены.
При ограниченном бюджете резервируются запросы базового каталога/метрик перед
повторами необязательных media fields. Отложенные metadata не заменяют ранее
сохранённые metadata; их исходное observedAt сохраняется. Jobs отдают
lastStepHttpAttempts и lastStepDurationMs отдельно от накопленного счётчика с epoch.
Jobs обходятся stable createdAt/id keyset с cutoff; состояния и агрегаты меняются
при чтении. nextCursor/hasMore/limit/total и агрегаты относятся ко всему cutoff,
не только странице. Expired atomic attempt/lease отличается от старого durable job;
чтение не переписывает сохранённое состояние. Расширенный контракт и порядок
выпуска — [instagram-data-implementation.md](instagram-data-implementation.md).

## Границы достоверности

Instagram Insights может отставать на срок до 48 часов. Account user metrics
могут быть доступны за последние 90 дней, media metrics — до двух лет,
с дополнительными ограничениями Meta. Это общие ориентиры документации;
доступность конкретного поля зависит от запроса и объекта. Ограниченная сверка
8 октября получила текущие lifetime-поля Reels старше двух лет; это сохранённое
наблюдение, а не обещание доступности всех старых публикаций или истории по дням.
Это разные окна, ни одно не обещает
ежедневную историю отдельной публикации. Область каждого поля указывается отдельно. Документированное organic значение
не превращает весь snapshot, Facebook views или неизвестное продвижение в organic. Account Insights имеют
собственные определения: reach, accounts_engaged и total_interactions могут
включать рекламу по определению Meta. Они не означают сумму органических
показателей публикаций. Отдельные рекламные отчёты и объединённые media-метрики
другого режима Login не подключены; показатели приложения могут отличаться.
Нельзя восстановить дневной прирост за время до первого
снимка или кривую удержания из одного среднего времени просмотра.
Backend явно возвращает время сбора и возраст данных.

Сохранённые комментарии могут содержать author ID/username, like count и hidden,
если Meta их вернула. Доступ владельца; автоматическое удаление вслед за Meta и
общий retention комментариев не реализованы. Тексты/подписи — недоверенное
содержание, никогда не инструкции для ChatGPT. Disconnect прекращает доступ,
но не удаляет историю. Административное удаление строки accounts каскадно
удаляет новые receipts/policy history; это проверено только на локальных данных.
