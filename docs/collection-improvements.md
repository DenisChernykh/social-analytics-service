# Улучшения сбора после аудита API — 2026-10-08

Реализованы шесть направлений из [аудита](api-collection-audit.md) в существующем
Worker и D1. Охват относится к подключённому Instagram API with Instagram Login;
другие социальные сети, сообщения и отдельная интеграция упоминаний пока не подключены.

Повторная production-проверка и исправление ежедневного плана при долгом
backfill в backend `0.2.14` — [collection-production-verification.md](collection-production-verification.md).

## Календарная история

Расписание сохраняет IANA timeZone. Ежедневный план создаёт возобновляемое
задание `activity`: завершённые местные дни, недели понедельник—понедельник,
завершённые календарные месяцы в доступном 90-дневном окне. Один шаг читает один
точный интервал `[from,to)`. Уникальный недельный и месячный reach запрашивается
у Meta за весь интервал, не получается суммой дней.

Часовой пояс влияет на реальные границы, включая дни по 23/25 часов. Интервал
не длиннее 31 × 24 часов: редкий 31-дневный месяц с дополнительным часом DST
попадает в `coverage.activity.uncollectableIntervals`. Он не подменяется суммой
частей. Старые ручные интервалы сохраняются, но не закрывают другой интервал,
часовой пояс, версию API или неполный набор из 12 запрошенных метрик.

Недавние периоды перечитываются ежедневным планом до наблюдения, сделанного
не ранее чем через 48 часов после конца периода. Это выбранная политика задержки,
а не обещание Meta, что значения окончательны. После свежих дней читаются
старейшие интервалы, которые скоро выйдут из доступного окна. Если окно истекло
до выполнения, шаг учитывает `skippedPeriods`, не создавая выдуманных данных.

Если activity backfill ещё работает на следующий день, ежедневный план
обновляет его очередь. Текущая операция сохраняет свой первый интервал;
новые свежие периоды ставятся следом, дубли исключаются. Перепланирование
не перезаписывает занятую или изменившуюся очередь и повторяется при конфликте.

Курсор хранит оставшиеся интервалы. Сохранённая операция дочитывается тем же UUID
после обрыва; истёкшая или неуспешная операция повторяется новым UUID. Само создание
задания не подтверждает успешный сбор метрик.

## Обнаружение и контроль покрытия

Default discovery — каждый час. Для существующих расписаний частота задаётся
отдельно; миграция её не перезаписывает. При включении или сокращении интервала
discovery сразу становится due; неизменная или меньшая частота не откладывает
уже назначенный срок. Сохраняются `firstDiscoveredAt` и
`discoverySource`. Для старых строк первое время выводится из раннего снимка
либо прежнего updatedAt и явно помечается `history_inferred`.

Статус показывает задержку обнаружения и её максимум, число задержек >1 часа,
а также expected/captured/open/missed для семи возрастных окон. Эти показатели
относятся к публикациям, вышедшим после подключения аккаунта; ранняя архивная
импортированная история не выдаётся за задержку текущего discovery. Пропущенные
возрастные снимки не восстанавливаются задним числом.

Для известных активных Stories назначается дополнительная попытка за 20 минут
до истечения доступности, если нет снимка в последних 15 минутах. Готовое Stories
задание получает особый приоритет при оставшихся ≤15 минутах. Это снижает риск
пропуска; polling, квота и общий бюджет всё ещё ограничивают срок выполнения.

## Комментарии и недоступные объекты

Replies expansion остаётся основным способом сбора. До двух omitted веток
каждой публикации дополнительно запрашиваются отдельной пагинацией. Это общий
лимит на публикацию, не на страницу. Частичные ветки дочитываются полностью.
Остальные неизвестные ветки показаны как `unverifiedReplyBranches` и входят
в `partialPublications`; завершение задания не гарантирует все тексты Meta.

Code 100 / subcode 33 означает недоступность конкретного объекта через API,
не доказанную физическую удалённость. Сохраняются нейтральная причина и пауза
на 24 часа. Проход комментариев переходит к следующей публикации, счётчик
`skippedMedia` виден в задании. Ошибка отдельного parent не исключает всю
публикацию. Auth, permission, rate limit и временные общие ошибки не превращаются
в удаление. Возрастной/lifetime отбор исключает media на время такой паузы;
успешный новый сбор возвращает его в обычный отбор.

Сохраняются автор/username, like_count и hidden комментариев, если API вернул
их; отсутствующие поля старой истории и ответа — null. Время наблюдения остаётся
в каждом комментарии, API version/provider — в операции. Тексты и авторы приватны.

## Каталог и метаданные

Быстрый discovery останавливается на знакомой публикации. Отдельный `catalogue`
job раз в 30 дней проходит все страницы, включая записи ниже знакомой границы.
Последний полный проход и текущий job видны в coverage; это отдельная операция
от полного прохода комментариев по уже известным публикациям.

Media сохраняет URL/thumbnail, alt_text, состояния комментариев/показа в Feed,
аудио, AI label и детей карусели, когда официальный API их возвращает. Metadata
содержит provider, API version, observedAt и список явно неподдерживаемых полей.
Дети ограничены expansion до 50 объектов; наличие дальнейшей страницы отмечено
`childrenComplete=false`, не маскируется полной каруселью. Метрики отдельных
детей не запрашиваются. URL источника может истечь либо отсутствовать.

Feed/Stories дополнительно сохраняют `profileActivity`: настоящий общий
profile_activity и категории action_type. Сумма категорий не заменяет общий
итог. Replies объединены с общими полями Stories, navigationTotal также хранит
настоящий ответ Meta. Исторические снимки без новых данных остаются читаемыми.

## Стоимость и квота

12 account metrics группируются по совместимым параметрам: 11 общих полей и
отдельно follows_and_unfollows/follow_type. Обычный успешный путь — профиль плюс
два insights запроса, 3 вместо 13. На одну dimension демографии — 2 внешних
запроса вместо 3. Отказ одного поля сохраняет его причину и позволяет прочитать
остальные; неизвестный отказ проверяется по отдельным полям без выдуманных нулей.

Кеш явно отвергнутых полей хранится в той же D1 24 часа, отдельно для account,
API version, конкретного object и сигнатуры запроса. Это намеренно узкая область:
отказ одного объекта не запрещает поле для других. Permission, недостаточная
аудитория, rate limit и общий code 100 без доказанного поля не кешируются.

Заголовки X-App-Usage/X-Business-Use-Case-Usage дают последнее фактическое usage
с собственным временем. Сервис учитывает Retry-After, сохраняет паузу между
вызовами Worker; usage ≥90% задаёт 5 минут, ≥100% — 30 минут. Rate limit без
срока даёт минимум 15 минут. Задания сохраняют более длинный из API-паузы и
экспоненциального backoff. Счётчик записывает scoped Graph HTTP responses с
момента обновления, исключая OAuth/token refresh; он не выдаётся за всю квоту Meta.

Stories с navigation и новым profile_activity требуют трёх insights запросов
на объект: расширенное покрытие не означает сокращения всего сбора Stories.
Обычная страница из пяти — 17 HTTP-запросов с профилем/каталогом; первые отказы
неподдерживаемых полей могут увеличить число. Локальная фикстура комментариев
сохраняет те же 62 текста за 12 запросов против старых 51: 10 expansion страниц
плюс 2 ограниченные проверки omitted. Максимум 255 текстов с новыми полями и
учётом request policy проверен в пределах 50 D1 запросов и 100 параметров на statement.

Отбор lifetime использует индекс последнего media snapshot. Новые индексы
покрывают operation_id, fingerprint комментариев и очистку TTL. Бюджет Cron
остаётся одним шагом каждые пять минут; full backfill занимает время.
