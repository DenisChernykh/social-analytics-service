`59cbcb2`, version `d975aa55-7484-4462-9a05-1a6ac1f82acd`, 100% traffic.

`062b2f9c4bc306bc66c53837e561950650f302221d7511cee7f814ea30f94667`.

invocation logs выключены, прежние D1/DO/Cron bindings сохранены.

- Stories discovery запрашивает до 50 объектов, а атомарная порция метрик
  по-прежнему обрабатывает один. Оставшиеся ID и source cursor хранятся в
  существующем cursor задания; продолжение переживает пересоздание клиента.
  Контрольный реальный проход завершил 4 страницы / 4 Stories без ошибки
  курсора и пропусков; список действительно запрошен с limit=50. Продолжение
  выполнили штатные alarms, без ручного advance.
- Повтор source cursor отклоняется до повторных insights и записи снимков.
  Неполный проход сохраняет ошибку и курсор; completed не подставляется.

  три поля reach/views/saves/shares, после первого core-прохода всех объектов
  страницы. Общий бюджет остаётся 6 HTTP attempts. Изолированный отказ reach
  не должен уничтожать доступные views/saves. Причина 100/2108006 по-прежнему
  не установлена; числовой подкод не объявляется признаком unsupported.
- Повторные объектные ошибки увеличивают паузу 5/10/20/40 минут и далее до
  суток; больший Retry-After источника сохраняется. Успех сбрасывает паузу.

  в существующей D1; редактирование названия не сбрасывает retry state.
- Новый read-only `GET /api/accounts/{accountId}/collection/jobs` возвращает
  только jobs/jobsPage. MCP использует его для cursor-продолжений и сохраняет
  полную первую сводку; для ответа о текущей очереди достаточно aggregates.
  Старый полный collection status сохраняет совместимость.
- Убраны вложенные JSON-переборы обязательных activity metrics, сокращены
  JSON-проверки полезности снимков и чтение истории для возрастного покрытия.
  Реальные нули, null и неизвестные дополнительные поля сохраняют смысл.

тестов, типы, границы, форматирование, контракт, dry-run и сборка MCP.
Проверены возрастные границы покрытия, реальные нули в неизвестных полях,
общий HTTP-бюджет, восстановление очереди Stories и сохранность retry state
при изменении названия. При откате старого backend сначала завершить новые
running Stories с `stories:v1:` cursor; старый адаптер этот формат не понимает.
Добавленную колонку при откате не удалять: старый код её игнорирует.

Установленный MCP подтвердил cursor-продолжение только с jobs/jobsPage,
без повторной тяжёлой диагностики. На трёх автоматически обновлённых
отказных публикациях даже изолированные поля по-прежнему получили
100/2108006: views/reach/saves остались null; новая начальная пауза 5 минут

## Meta

1. В сценарии Instagram включить `instagram_business_basic` и
   `instagram_business_manage_insights`.
2. Открыть настройку API для входа в Instagram и настройку business login.
3. Зарегистрировать точный redirect URI:
   `https://api.social-insights.workers.dev/api/instagram/oauth/callback`.
4. Для приложения в режиме разработки назначить подключаемому Instagram
   аккаунту роль тестировщика и принять приглашение в настройках аккаунта,
   если это требуется Meta.
5. Сохранить Instagram App ID/Secret локально и в Worker Secrets; выполнить
   `pnpm api connect`, подтвердить доступ к нужному аккаунту в Instagram.

По умолчанию запрашиваются только basic и manage_insights. Чтение комментариев
подключается отдельно: добавить `instagram_business_manage_comments` в настройку
приложения и выполнить `pnpm api connect --comments`; официальный экран OAuth
подтверждает владелец. Права публикации, сообщений и рекламы не запрашиваются.
Аккаунт должен быть профессиональным.
Доступ для пользователей вне ролей приложения потребует отдельной настройки
Meta и проверки приложения; эта установка предназначена для владельца.

Для настройки существующего приложения Meta опубликованы информационные
адреса backend: [политика конфиденциальности](https://api.social-insights.workers.dev/privacy-policy)
и [инструкции удаления данных](https://api.social-insights.workers.dev/data-deletion).
Они не открывают доступ к статистике: `/api/accounts` без ключа возвращает 401.
Контакт использует ранее согласованный адрес владельца. Эти страницы сами по себе

## Cloudflare и секреты

Не переключайте глобальный профиль других проектов. Проверка входа выполняется
из `backend` после активации профиля для этого каталога:

```sh
pnpm --dir backend exec wrangler auth activate social-analytics .
pnpm --dir backend exec wrangler whoami
```

Обязательные Worker Secrets: `API_KEY`, `TOKEN_ENCRYPTION_KEY`,
`INSTAGRAM_CLIENT_ID`, `INSTAGRAM_CLIENT_SECRET`. Значения читаются из закрытого
локального файла и передаются Wrangler через stdin; не помещайте секреты в
аргументы команд, вывод, документацию или репозиторий.
Для callback комментариев нужен также `INSTAGRAM_WEBHOOK_VERIFY_TOKEN`;
его создаёт `pnpm setup:local`. Настройка и критерии реальной доставки описаны в
[comment-collection-optimization.md](comment-collection-optimization.md).

Локальные `.dev.vars`, Wrangler state/logs и сборка исключены из Git.
Отсутствующие секреты не заменяются открытыми значениями в конфигурации Worker.
Объявленный в конфигурации список секретов делает генерацию типов независимой
от содержимого локального файла.

`pnpm secrets:upload` загружает четыре обязательных значения и настроенный
verify token из `.dev.vars` через stdin,
используя только профиль `social-analytics` и Worker из конфигурации. Команда
не выводит значения или вывод Wrangler. При первом запуске Wrangler может
создать Worker для сохранения секретов; затем следует deploy проверенного кода.

Перед ручным развёртыванием:

```sh
pnpm db:migrate:local
pnpm check
pnpm secrets:upload
pnpm --dir backend exec wrangler d1 migrations apply social-analytics-db --remote
pnpm --dir backend exec wrangler deploy
```

Удалённые миграции и deploy выполняют только в авторизованном аккаунте после
проверок. Миграции 0002–0004 добавляют таблицы дорожной карты и поля истории/контекста
в существующей D1, сохраняя старые наблюдения и подключения. Другие приложения
и базы не затрагиваются. Новые secrets не нужны; повторно загружать их при
обычном обновлении кода не требуется.
Invocation logs и Observability отключены, чтобы OAuth callback не попал в логи.
Платные ресурсы не добавлены.

После развёртывания проверить `/health`, `/openapi.json`, отказ API без ключа,
доступ с ключом, реальное подключение Instagram, успешный сбор одной страницы

При rate limit сделать паузу и продолжить с `nextCursor` последней успешной
