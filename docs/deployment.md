# Настройка и эксплуатация

Cloudflare Worker: `api`, адрес `https://api.social-insights.workers.dev`.
D1: `social-analytics-db`, binding `DB`. Account ID и Database ID закреплены
в `backend/wrangler.jsonc`. Используется отдельный профиль Wrangler
`social-analytics`, привязанный только к этому проекту.

Meta-приложение: **Social Analytics**, parent App ID `1538788254718612`.
Instagram-продукт: **Social Analytics-IG**, Instagram App ID `1703655370738343`.
Backend использует Instagram App ID и его секрет. Почта и аккаунты согласованы
с владельцем; приложение создавалось под текущим входом Meta без бизнес-портфолио.

## Meta

1. В сценарии Instagram включить `instagram_business_basic` и
   `instagram_business_manage_insights`.
2. Открыть настройку API для входа в Instagram и настройку business login.
3. Зарегистрировать точный redirect URI:
   `https://api.social-insights.workers.dev/api/instagram/oauth/callback`.
4. Для приложения в режиме разработки назначить подключаемому Instagram
   аккаунту роль тестировщика и принять приглашение в настройках аккаунта,
   если это требуется Meta.
5. Сохранить Instagram App ID/Secret локально и в Worker Secrets; выполнить
   `pnpm api connect`, подтвердить доступ к нужному аккаунту в Instagram.

По умолчанию запрашиваются только basic и manage_insights. Чтение комментариев
подключается отдельно: добавить `instagram_business_manage_comments` в настройку
приложения и выполнить `pnpm api connect --comments`; официальный экран OAuth
подтверждает владелец. Права публикации, сообщений и рекламы не запрашиваются.
Аккаунт должен быть профессиональным.
Доступ для пользователей вне ролей приложения потребует отдельной настройки
Meta и проверки приложения; эта установка предназначена для владельца.

Документация:
[Instagram Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/),
[Business Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/business-login/),
[API versions](https://developers.facebook.com/docs/graph-api/changelog/versions/).

## Cloudflare и секреты

Не переключайте глобальный профиль других проектов. Проверка входа выполняется
из `backend` после активации профиля для этого каталога:

```sh
pnpm --dir backend exec wrangler auth activate social-analytics .
pnpm --dir backend exec wrangler whoami
```

Обязательные Worker Secrets: `API_KEY`, `TOKEN_ENCRYPTION_KEY`,
`INSTAGRAM_CLIENT_ID`, `INSTAGRAM_CLIENT_SECRET`. Значения читаются из закрытого
локального файла и передаются Wrangler через stdin; не помещайте секреты в
аргументы команд, вывод, документацию или репозиторий.

Локальные `.dev.vars`, Wrangler state/logs и сборка исключены из Git.
Отсутствующие секреты не заменяются открытыми значениями в конфигурации Worker.
Объявленный в конфигурации список секретов делает генерацию типов независимой
от содержимого локального файла.

`pnpm secrets:upload` загружает четыре значения из `.dev.vars` через stdin,
используя только профиль `social-analytics` и Worker из конфигурации. Команда
не выводит значения или вывод Wrangler. При первом запуске Wrangler может
создать Worker для сохранения секретов; затем следует deploy проверенного кода.

Перед ручным развёртыванием:

```sh
pnpm db:migrate:local
pnpm check
pnpm secrets:upload
pnpm --dir backend exec wrangler d1 migrations apply social-analytics-db --remote
pnpm --dir backend exec wrangler deploy
```

Удалённые миграции и deploy выполняют только в авторизованном аккаунте после
проверок. Миграции 0002–0004 добавляют таблицы дорожной карты и поля истории/контекста
в существующей D1, сохраняя старые наблюдения и подключения. Другие приложения
и базы не затрагиваются. Новые secrets не нужны; повторно загружать их при
обычном обновлении кода не требуется.
Invocation logs и Observability отключены, чтобы OAuth callback не попал в логи.
Платные ресурсы не добавлены.

После развёртывания проверить `/health`, `/openapi.json`, отказ API без ключа,
доступ с ключом, реальное подключение Instagram, успешный сбор одной страницы
и отчёт из сохранённого снимка. Затем запустить полный обход публикаций.
При rate limit сделать паузу и продолжить с `nextCursor` последней успешной
страницы. Неудачная операция не повторяет сеть при том же UUID — используйте
новый UUID после устранения причины.

В ревизии 0.2.0 полный сбор поддерживает сохраняемое задание и продолжение
по job ID: `pnpm api collect ACCOUNT_ID [JOB_ID]`. Cron существующего Worker
продвигает задания и выполняет только явно включённые расписания. Автоматический
сбор по умолчанию выключен. Observability/invocation logs остаются отключены.

После обновления доступна воспроизводимая проверка без вывода OAuth, токенов,
текстов комментариев или личных значений метрик:

```sh
node scripts/verify-backend-roadmap.mjs
node scripts/verify-backend-roadmap.mjs --refresh --insights --audience --stories --comments
```

Первый вызов только читает. Флаги явно создают настоящие наблюдения: refresh
одной публикации, Account Insights двух равных семидневных периодов и разных
type/breakdown, четыре разбивки демографии, ограниченный discovery Stories и
страницу комментариев при наличии согласия. Отсутствие Stories/permission
отражается в результатах, а не подменяется успешными фиктивными данными.
Контекст, бизнес-записи и гипотезы проверяются локально без тестовых записей
в production.

текстов у выбранного объекта не означает, что комментариев в Instagram нет.

`pnpm api collect` завершил полный каталог в одном сохраняемом задании:
236 страниц/наблюдений, status=completed, cursor=null. Отдельное расписание
осталось выключенным. Устаревшие диагностические Stories jobs остановлены.

одинаковом возрасте видны. Нужная история будет появляться с реальными
наблюдениями, а не заполняться задним числом.
