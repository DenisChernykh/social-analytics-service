Исторические измерения ниже относятся к 0.2.12. После публикаций 0.2.13 и
0.2.14 требуется новое суточное окно для актуальной версии; прежний срок

## Подписка и реальное событие, 2026-10-08 UTC

В Meta Dashboard существующего приложения Social Analytics подтверждён callback
`https://api.social-insights.workers.dev/webhooks/instagram/comments` с локально
настроенным verify token. Поле `comments` подписано. Секреты не выводились.
Официальный `subscribed_apps` через защищённый backend подтвердил подписку
подключённого аккаунта в `04:03:12.539Z`.

После нового комментария, опубликованного владельцем для проверки, Worker
получил реальное событие Meta в `04:08:30.519Z`; время события — `04:08:29Z`.
Подпись и принадлежность аккаунта прошли проверку; статус сообщает
`webhook.active=true`. Событие повысило generation публикации до 1. Scheduler
создал отдельный `comments_refresh` в `04:11:05.131Z`, сохранив текущий полный
проход и общий бюджет одного шага.

Штатный Cron прочитал первую страницу с пятью наблюдениями в `04:16:09.691Z`.
Новый непустой текст сохранён: SHA-256 от его ID, parentId, текста и идентичности
события точно совпал с сохранённым digest webhook. Проверка выполнена в памяти;
текст и токены не выводились. `publishedAt=04:08:26Z` получен отдельным чтением
официального API, `observedAt=04:16:09.691Z`; время доставки не подменяет время
публикации. Задержка между доставкой и наблюдением составила 459,172 секунды
в этом запуске, без гарантии такой задержки для следующих событий.

Refresh job остаётся `running`, одна страница, пять наблюдений, без ошибки;
`processedGeneration=0` до окончания доступной пагинации. Сохранение проверенного
комментария не объявляет завершёнными остальные страницы публикации. Старый
полный проход также продолжает работать, 163/236 публикаций, 73 остаются.

## Первые 6,5 часа после исправления

Агрегаты получены из официального GraphQL API Cloudflare 2026-10-08.
Сравниваются равные интервалы UTC с границами `[start, end)`:

- `0.2.10`: 2026-10-06 21:30 — 2026-10-07 04:00.
- `0.2.12`: 2026-10-07 21:30 — 2026-10-08 04:00.

`workersInvocationsAdaptive` фильтруется по существующему Worker `api`.
Суммы и quantiles запрошены без группировки; отдельная группировка `status`
в обоих интервалах вернула только `success`. CPU и wall time API сообщает
в микросекундах; значения ниже переведены в миллисекунды делением на 1000.
`d1AnalyticsAdaptiveGroups` фильтруется по существующей production D1.
