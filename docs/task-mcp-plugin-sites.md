# Social Analytics: MCP и плагин на Sites

Результат этой задачи и проверки: [mcp-plugin-sites.md](mcp-plugin-sites.md).
Social Analytics — проект и плагин для всех соцсетей владельца;
Instagram — первая готовая интеграция.

## Задача новой сессии

Создать MCP и плагин Social Analytics с размещением на Sites, используя готовый
backend. Пользователь отдельно запросил эту следующую задачу после завершения
backend. Ограничение «backend only / no MCP or plugin in this task» в AGENTS.md
относилось к предыдущей задаче; новая задача явно разрешает MCP и плагин.
Остальные архитектурные правила и требования к секретам сохраняются.

Целевой сценарий: пользователь пишет в ChatGPT «Мне нужна статистика по ролику
„Кино курьер“» и получает доступную статистику, вычисленные показатели и
объяснение ограничений. «Кино курьер» — пример запроса, а не конкретный ролик;
пользователь уже подтвердил это, искать для него публикацию не требуется.

## Требуемое поведение

Реализовать безопасный адаптер к backend и инструменты MCP для поиска
публикаций по названию, подписи или ссылке, получения полного отчёта,
истории, сравнения с другими публикациями, сводки аккаунта и описаний метрик.
Поддержать сохранение локального названия публикации, если это нужно для
поиска по удобному имени. При нескольких совпадениях вернуть кандидатов и
запросить выбор; не выбирать первый ролик молча.

При необходимости обновления статистики использовать существующий sync API
с его пагинацией, идемпотентностью и проверкой статуса. Проверить точные
маршруты и схемы по OpenAPI; не придумывать новые возможности backend.
Сейчас нет автоматического расписания и отдельного endpoint обновления одного
ролика: отчёты читают сохранённые снимки. Указывать время сбора и свежесть
данных; не обещать статистику в реальном времени.

Проверить актуальный формат MCP и плагина по официальной документации и
возможности Sites. Подготовить конфигурацию, инструкции и пригодный для
подключения результат; проверить реальный путь запроса от инструмента до
backend. Пользователь попросил именно Sites. Использовать средства Sites
для размещения MCP и необходимые инструкции платформы, сохраняя приватный
доступ по умолчанию. Итоговые пояснения и инструкции дать по-русски.

## Семантика данных

- `/api/reports/media` возвращает `matched`, `ambiguous` или `not_found`.
- Статистика включает исходные метрики и производные показатели с формулами,
  исходными значениями, единицами, временем сбора и причинами недоступности.
- Недоступная метрика — `null`, доступный ноль — `0`. Не придумывать retention,
  completion rate или историю до начала сбора.
- Период фильтрации сводки означает даты публикаций, а показатели являются
  накопленными значениями. Охват разных публикаций нельзя складывать как
  уникальную аудиторию. Показывать полноту, `knownSum` и размер выборки.
- История роста требует реальных снимков. Сравнение с другими роликами
  должно сохранять оговорки о возрасте публикаций и размере выборки.
- Ручное название и известная длительность сохраняются локально и не меняют
  публикацию в Instagram. Длительность нужна для средней доли просмотра;
  эта доля не является процентом досмотров.

## Доступ и ограничения пользователя

API защищён `Authorization: Bearer API_KEY`; OAuth callback — исключение.
Секреты находятся в Cloudflare Worker Secrets и игнорируемом
`backend/.dev.vars`. Использовать их только через безопасную серверную
конфигурацию. Не печатать и не переносить значения в задачи, переписку,
документацию, репозиторий, клиентский код или логи. MCP и плагину не нужны
Instagram access token и Meta app secret: они обращаются к backend.

Cloudflare для backend использует изолированный профиль Wrangler
`social-analytics`. Не менять глобальный профиль других проектов.
Сохранять границы модулей; не добавлять платную инфраструктуру по умолчанию.
Не публиковать статистику и секреты через общедоступный сайт.

Пользователь запрещает автоматически подставлять новые почту, домен или
аккаунты: новые данные необходимо запросить. Уже согласованные сведения:
контактная почта Meta `sharper.togas-6q@icloud.com`, указанный адрес backend,
подключённый Instagram и текущая учётная запись Meta без бизнес-портфолио.
Для Chrome использовать обычные инструменты взаимодействия с открытым
Chrome; пользователь исключил Playwright и browser skills других плагинов.
Документацию можно читать без открытия вкладок.

## Критерии завершения

MCP доступен через Sites с корректной авторизацией; плагин подготовлен в
актуальном поддерживаемом формате и проверен вместе с MCP. Проверены поиск,
неоднозначный запрос, отчёт по реальной публикации, недоступные метрики,
свежесть и отсутствие утечки секретов. Предоставлены ссылки и конкретные
инструкции подключения. Если для окончательного подключения требуется
действие владельца, подготовлен проверенный результат и точно описан этот
оставшийся шаг.
